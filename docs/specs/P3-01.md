# P3-01 — Cliente HTTP y cold start (MUST)

**Rama** `fix/P3-01-cliente-cold-start` · **PR** mié 25 · **Merge** jue 26 · **Dueño** P3

## Objetivo
Que la web nunca muestre errores crudos cuando Render está dormido o responde HTML, y que el usuario sepa que la API "está despertando".

## Contexto
`src/services/api/cliente.ts:76-125` (`JSON.parse(texto)` sin protección en :109; mensaje "sin conexión" en :101-104), `src/hooks/useConsulta.ts` (AbortController), `src/config/api.ts:5-7` (`VITE_API_URL` con fallback a `localhost:8080`). Render free tarda ~1 min en despertar.

## Cambios
1. `cliente.ts`: si la respuesta no es JSON válido (502/503, HTML), lanzar `ApiError` con `regla=SERVICIO_NO_DISPONIBLE` y mensaje amable en español, en vez de `SyntaxError`.
2. Aviso global "La API está despertando, puede tardar hasta un minuto…" cuando una petición pasa de ~4 s; desaparece al responder. Implementar en `useConsulta`/contexto y mostrarlo en un componente pequeño (banner) sin bloquear la UI.
3. Reintento automático de 1 vez con espera corta para GET si el error es de red/502/503.
4. Si el build de producción no tiene `VITE_API_URL`, mostrar un aviso visible en consola y banner (no apuntar silenciosamente a localhost).

## Criterios de aceptación
- Dado un 502 con cuerpo HTML → `ApiError` con `regla=SERVICIO_NO_DISPONIBLE` (no `SyntaxError`).
- Dada una petición > 4 s → aparece el banner y desaparece al terminar.
- Los tests actuales de `tests/unit/cliente.test.ts` siguen pasando.

## Tests
Ampliar `tests/unit/cliente.test.ts`: respuesta HTML, timeout simulado con fake timers, reintento GET.

## Fuera de alcance
Modo offline, service workers.

## Verificar
`pnpm test && pnpm typecheck && pnpm lint`; manual: apagar el backend local y ver el mensaje.
