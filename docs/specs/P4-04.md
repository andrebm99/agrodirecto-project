# P4-04 — Pruebas de pantallas y E2E de navegador (SHOULD)

**Rama** `test/P4-04-e2e-frontend` · **PR** sáb 28 · **Merge** dom 29 · **Dueño** P4

## Objetivo
Detectar regresiones del flujo completo desde el navegador con los 4 roles.

## Contexto
Hay 4 archivos unitarios (`tests/unit/`, 19 pruebas) y `tests/rendered-html.test.mjs`. `vitest.config.ts:8` usa `environment: "node"`, sin DOM ni `@testing-library`. Backend con `compose.yaml` (MySQL + API) y datos demo `V2__datos_demo.sql`.

## Cambios
1. (Primero) Añadir `@testing-library/react` + `jsdom` solo para los tests de componentes (entorno por archivo con `// @vitest-environment jsdom`); tests de `Checkout`, `Orders`, `Login`, `EstadoError`.
2. Playwright (`tests/e2e/`): arranca el backend con `compose.yaml` y datos demo; escenarios:
   - Comprador: login → catálogo → carrito → checkout → pedido visible.
   - Agricultor: login → acepta pedido → marca entregado.
   - Comprador: confirma recepción y reseña.
   - Disputa: abrir, descargo, resolución por admin (con 2FA demo usando secreto por variable).
   - Agente: registra y verifica un agricultor.
3. Script `pnpm test:e2e` y job opcional en CI (manual `workflow_dispatch` para no alargar los PR).

## Criterios de aceptación
- `pnpm test:e2e` pasa localmente contra el entorno docker.
- Los escenarios cubren los 4 roles. Un fallo deja captura/trace.

## Fuera de alcance
Pruebas visuales, carga, cross-browser (solo Chromium).

## Verificar
`docker compose up` en el backend + `pnpm test:e2e`.
